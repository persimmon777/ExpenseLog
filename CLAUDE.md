# Spent — учёт расходов для iPhone

Личное iOS-приложение: разбирает SMS банка об операциях по карте, раскладывает траты по категориям, показывает аналитику, ведёт долги и лимиты, показывает виджет «Траты за сегодня».

Язык интерфейса и комментариев в коде — **русский**. Общение с владельцем — на русском.

**Владелец пишет приложение впервые и не программист.** В конце **каждого** ответа — блок «Что делать вам» с пронумерованными шагами: куда нажать, что открыть, что проверить (ссылки — полные). Если от владельца сейчас ничего не нужно — так и написать и сказать, что будет дальше. Без жаргона; термины пояснять одной фразой.

**Выкладка:** после успешной сборки на рабочей ветке — самостоятельно создать PR в `main` и влить его (владелец разрешил), проверить, что релиз `latest` обновился. Ссылку https://github.com/persimmon777/ExpenseLog/releases/download/latest/Spent.ipa присылать владельцу, когда в новой версии важно его мнение (новые экраны, дизайн).

## 0. Условия, которые определяют всё остальное

- **У владельца нет Mac.** Ноутбук на Windows, iPhone 12 с **iOS 17.4.1**.
- **Скомпилировать код можно только в GitHub Actions** (облачный macOS). Локальной проверки нет, поэтому каждое изменение должно быть «компилируемым с первого раза»: никаких сомнительных API, всё новее iOS 17 только под `#available`. После пуша проверяй лог сборки.
- **Установка через SideStore** с бесплатным Apple ID:
  - подпись живёт 7 дней, SideStore продлевает её сам;
  - максимум 3 приложения одновременно (SideStore + Spent уже 2), 10 App ID за 7 дней: приложение и виджет занимают 2;
  - **нет iCloud/CloudKit, push-уведомлений (APNs), Face ID-entitlement-ов** — только то, что работает без платного аккаунта;
  - SideStore при переподписи меняет идентификатор App Group (дописывает ID команды) и кладёт настоящий в Info.plist под ключом `ALTAppGroups`. Это уже учтено в `AppGroup` (`Shared/DataFile.swift`) — **не хардкодить группу напрямую**.
- Проект описывается **только через XcodeGen** (`project.yml`). `.xcodeproj` в репозиторий не коммитим (он в `.gitignore`).

## 2. Как операции попадают в приложение

iOS **не позволяет** приложениям читать SMS. Используется **«Быстрые команды» → «Автоматизация»**:

1. Владелец один раз создаёт автоматизацию: «Сообщение» → «Сообщение содержит: **BYN**» → «Запускать немедленно» → действие **Spent → «Добавить SMS банка»**, в параметр «Текст SMS» передаётся «Ввод быстрой команды» → «Содержимое».
2. На iOS 17 автоматизация по сообщению срабатывает **без подтверждения**.
3. App Intent `AddBankSMSIntent` (`openAppWhenRun = false`) вызывает `DataFile.update { $0.ingest(smsText:) }`, затем: проверка лимитов → пересчёт еженедельного уведомления → резервная копия (если разрешено) → `WidgetCenter.shared.reloadAllTimelines()`.
4. SMS, которые не являются операцией (коды, реклама), **молча игнорируются** — автоматизация срабатывает на все сообщения с «BYN».

Инструкция по настройке автоматизации — отдельный экран в приложении (Настройки → «Автодобавление из SMS»), по шагам, с русскими названиями пунктов iOS 17.

Второй путь — **«Вставить SMS»** на экране «Чеки»: текст из буфера (одно или пачка SMS) → предпросмотр разобранных операций → «Добавить N».

### App Intent (спецификация)

```swift
struct AddBankSMSIntent: AppIntent {
    static var title: LocalizedStringResource = "Добавить SMS банка"
    static var description = IntentDescription("Разбирает SMS о списании, пополнении или снятии наличных и добавляет операцию в Spent.")
    static var openAppWhenRun = false
    @Parameter(title: "Текст SMS") var text: String
    func perform() async throws -> some IntentResult & ReturnsValue<String>
}
struct SpentShortcuts: AppShortcutsProvider { /* фраза: "Добавить SMS в \(.applicationName)" */ }
```

## 3. Форматы SMS

Банк присылает SMS латиницей. Общая структура:

```
<ТИП> <СУММА> <ВАЛЮТА>  KARTA #<4 цифры> DATA <ДД.ММ.ГГГГ> <ЧЧ:ММ:СС> <МЕСТО>[>ГОРОД>СТРАНА] MCC:<4 цифры> OSTATOK <СУММА> <ВАЛЮТА>
```

Переводы строк в SMS произвольные (перенос пузыря), парсер работает с `.dotMatchesLineSeparators` и регистронезависимо.

| Тип в SMS | `SMSType` | `TxKind` | Пример |
|---|---|---|---|
| `OPLATA` | `.payment` | `.expense` (трата → «Без категории», если нет правила) | см. ниже |
| `POPOLNENIE KARTOCHKI` | `.topUp` | `.income` | см. ниже |
| `NALICHNYE` | `.cashWithdrawal` | `.transfer` (**снятие наличных — перевод, не трата**) | см. ниже |

### Реальные примеры и ожидаемый результат разбора

```
OPLATA 22.60 BYN  KARTA #7738 DATA 07.11.2026 20:41:16 OMBSHOP.OZON.BY>MINSKIY R-N>BY MCC:5300 OSTATOK 35.14 BYN
→ payment, 22.60 BYN, карта 7738, 07.11.2026 20:41:16, placeRaw «OMBSHOP.OZON.BY>MINSKIY R-N>BY», place «OMBSHOP.OZON.BY», MCC 5300, остаток 35.14

OPLATA 7.97 BYN  KARTA #7738 DATA 07.11.2026 20:41:16 OMBSHOP.OZON.BY>MINSKIY R-N>BY MCC:5300 OSTATOK 57.74 BYN
→ payment, 7.97 BYN, та же секунда, что и предыдущее — это ДРУГАЯ покупка (другой отпечаток), не дубль

POPOLNENIE KARTOCHKI 400.00 BYN  KARTA #7738 DATA 06.11.2026 17:49:22 INFOKIOSK 12723 CASH IN>MINSK>BY MCC:6011 OSTATOK 509.01 BYN
→ topUp, 400.00 BYN, place «INFOKIOSK 12723 CASH IN», MCC 6011, остаток 509.01

NALICHNYE 10.00 BYN  KARTA #7738 DATA 07.11.2026 16:04:14 BR.527/209 BR.795/795 ATM>MINSK>BY MCC:6011 OSTATOK 65.71 BYN
→ cashWithdrawal, 10.00 BYN, place «BR.527/209 BR.795/795 ATM», MCC 6011, остаток 65.71

Vash kod 1234 dlya vhoda
→ nil (игнор)
```

Эти примеры — **обязательные тест-векторы**. Если меняешь парсер, все они должны давать тот же результат. Без Mac регулярки проверяются скриптом `python3 Tools/parser_check.py` (копия регулярок из Swift — при изменении правь оба места). При добавлении тест-таргета — оформить те же векторы как XCTest.

### Правила разбора

- **Разбиение пачки** (`SMSParser.split`): по началу каждого ключевого слова `OPLATA|POPOLNENIE|NALICHNYE`; текст до первого слова отбрасывается.
- **Место** — всё между временем и `MCC:` / `OSTATOK` / концом. `place` = часть до первого `>`. В интерфейсе для `.topUp` и `.cashWithdrawal` показывать человеческое название («Пополнение», «Снятие наличных»), место — мелко.
- **Отпечаток** (`fingerprint`) — SHA-256 текста в верхнем регистре со схлопнутыми пробелами. Одинаковый текст = дубль, разный текст (даже в ту же секунду) = разные операции.
- **Удалённые SMS не возвращаются**: отпечаток удалённой операции хранится в `AppData.deletedFingerprints`; `ingest` такие пропускает (`IngestResult.previouslyDeleted`).
- **Остаток** (`OSTATOK`) обновляет `AppData.lastBalance`, только если операция не старше предыдущей с остатком.
- Неизвестный тип SMS → `nil`. Новые форматы добавлять в `SMSType` + `headRegex` + тест-векторы.

## 4. Типы операций (`TxKind`)

| Тип | Что это | В расходах? |
|---|---|---|
| `expense` | Трата | **да** — итоги, категории, лимиты, виджет, прогноз |
| `income` | Пополнение | нет, отдельный блок в аналитике |
| `transfer` | Перевод: снятие наличных, между своими картами, другу | нет |
| `debtGiven` | Деньги, данные в долг | нет — раздел «Долги» |
| `debtReturn` | Входящие деньги, закрывающие долг | нет (и не доход) |

Правило: **везде, где считаются расходы, фильтр — `tx.countsAsExpense`** (= `kind.countsAsExpense` и трата не исключена галочкой «Учитывать в расчёте трат», `Transaction.excludedFromTotals`). Тип любой операции меняется в одно касание (`AppData.setKind`). Категория есть только у `expense`.

## 5. Экраны (5 вкладок)

### 5.1 Чеки (главная)
- Карточка-«чек» сверху: **сегодня**, **за месяц**, **остаток на карте** (из последней SMS или указан вручную), **прогноз на конец месяца**.
- Строка **«Планируется»** — сумма примерных цен некупленного из **списка покупок** (`AppData.shoppingList`, `plannedTotal`); нажатие открывает `ShoppingListSheet`: галочки, примерные цены, «Осталось купить», «Останется на карте», «Убрать купленное», свайп — удалить/изменить. Планируемое в расходы не входит.
- Нажатие на «На карте» → **«Баланс карты»** (`setBalance`): ручной остаток на случай неучтённых операций; следующая SMS с остатком (новее) снова обновляет его (`balanceSetManually`).
- **«Без категории»** — неотсортированные траты (`AppData.uncategorized`). Нажатие → лист выбора категории:
  - сетка категорий (эмодзи + название + цвет), подсказка по MCC;
  - переключатель **«Всегда относить <магазин> к этой категории»** → `categorize(createRule: true)`: правило применяется ко всем неотсортированным в этом магазине и ко всем будущим;
  - кнопки **«Это перевод»** и **«Это долг»** (второе открывает форму долга: кому, дата возврата);
  - «Новая категория» прямо из листа.
  - **Режим разбора**: лист, открытый из «Без категории», после выбора категории (или «Это перевод» / «Это долг») сразу показывает следующую неотсортированную покупку («Осталось без категории: N», «Кафе ✓»); нет следующей — закрывается.
  - галочка **«Учитывать в расчёте трат»** (по умолчанию включена): выключенная трата остаётся в истории (сумма зачёркнута, «не в расчёте»), но не входит в итоги, категории, лимиты, виджет и «Без категории» (`setExcluded`).
- **История** по дням (заголовки «Сегодня», «Вчера», «5 ноября»), знак суммы по `isOutgoing`.
  - нажатие — тот же лист, но **не закрывается после выбора** — закрывает «Готово»: сменить категорию/тип, заметка, «Переименовать» магазин;
  - **удаление** (свайп) → операция сразу удаляется (`deleteTransaction`), снизу плашка **«Удалено · Отменить» на 5 секунд** → `restoreTransaction`. Удалённое SMS не вернётся при повторной вставке/автоматизации.
- Кнопки: **«+»** — ручная операция (сумма, описание, дата, тип, категория; например, траты наличными); **«Вставить SMS»** — разбор из буфера с предпросмотром и итогом («Добавлено 3, дублей 1, ранее удалено 1»).

### 5.2 Аналитика
- Переключатель **День / Неделя / Месяц**; по умолчанию — **текущий** период.
- **Календарь месяца** (свой, не `DatePicker`): неделя с понедельника; слева колонка с номером недели.
  - нажатие на день → режим «День»; на номер недели → «Неделя»; на название месяца → «Месяц»;
  - стрелки ‹ › листают месяцы;
  - под днями с тратами точка, яркость пропорциональна сумме.
- **Итог периода**: сумма трат, число покупок, сравнение с предыдущим таким же периодом («на 12% меньше, чем на прошлой неделе»).
- **Гистограмма по категориям** (Swift Charts, горизонтальные `BarMark`, цвет категории), суммы и проценты; «Без категории» — серым. Нажатие на категорию → список её операций за период.
- **Отдельными блоками, не смешивая с расходами**: пополнения, переводы, долги (выдано за период; сколько должны сейчас).
- **Поделиться** (меню в тулбаре):
  - «Отправить отчёт» — `ShareLink` с текстом (Telegram и любые приложения);
  - «Разобрать в DeepSeek» — копирует в буфер отчёт с промптом «Проанализируй мои траты за <период>. Где я трачу нерационально и что можно сократить?» и открывает `https://chat.deepseek.com`; тост «Отчёт скопирован — вставь его в чат DeepSeek». API DeepSeek не используем.

Формат текстового отчёта:
```
Spent: отчёт за ноябрь 2026
Потрачено: 412,37 BYN (37 покупок)
Продукты: 184,20 BYN (45%)
Одежда: 98,00 BYN (24%)
…
Без категории: 12,00 BYN
Пополнения: +400,00 BYN
Переводы: 10,00 BYN
Тебе должны: 85,00 BYN
```

### 5.3 Долги
- Список: **кому, сумма, когда дал, дата возврата**, отметка **вернули / не вернули**; сверху итог **«Тебе должны: N BYN»**; просроченные (`isOverdue`) подсвечены.
- Добавить вручную или из операции («Это долг» → `makeDebt(fromTransaction:)`).
- «Вернули» → `setDebtReturned`, можно выбрать входящую операцию — она станет `debtReturn` и не посчитается доходом.
- Удаление долга (`deleteDebt`) возвращает операцию выдачи в `transfer`.
- **Уведомление в день возврата в 10:00**: «Сегодня Петя должен вернуть 20 BYN».

### 5.4 Категории и лимиты
- CRUD категорий: название, эмодзи, цвет из `Category.palette`. Удаление (`deleteCategory`) — с подтверждением, траты становятся неотсортированными.
- **«Дал в долг» — не категория** (для этого «Долги»).
- **Лимит на месяц** (`monthlyLimit`): полоска прогресса у категории (зелёная → жёлтая с 80% → красная с 100%), подпись «64 из 80 BYN»; прогноз «при таком темпе лимит закончится ~20 ноября».
- Список правил «магазин → категория» с удалением.

### 5.5 Настройки
- Тема: «Чек» / «Карта».
- **«Магазины»** (`MerchantsView`): все магазины (покупки, сумма, последняя), поиск; у магазина — своё название (`AppData.merchantNames`, ключ `Merchant.key`, показ через `displayTitle` / `merchantName`) и категория «всегда относить» (`setRule`).
- Автодобавление из SMS — инструкция по автоматизации.
- Резервная копия: выбрать папку, статус последней копии, «Восстановить из копии».
- Уведомления: еженедельная сводка, лимиты, долги — отдельные переключатели (`SharedSettings.Key.notify*`, по умолчанию включены).
- Экспорт/импорт JSON вручную.

## 6. Лимиты и прогноз

- Траты категории за **текущий календарный месяц** / `monthlyLimit`.
- **Предупреждения при 80% и 100%** — локальное уведомление сразу после операции, которая пересекла порог (в приложении и в App Intent). Каждое — **один раз за месяц**: учёт в `AppData.limitAlertsSent["<categoryID>|yyyy-MM"] = 80|100`. Текст: «Кафе: потрачено 80% лимита (64 из 80 BYN)», «Кафе: лимит исчерпан (82 из 80 BYN)».
- **Прогноз на конец месяца** = траты с начала месяца / прошедшие дни (включая сегодня) × дней в месяце.
- **Дата исчерпания лимита** = сегодня + (лимит − потрачено) / средний расход категории в день (если темп > 0 и лимит ещё не исчерпан).

## 7. Уведомления (только локальные, `UNUserNotificationCenter`)

Разрешение запрашивать при первом включении любой функции уведомлений (или на первом запуске после онбординга).

| Что | Когда | Идентификатор |
|---|---|---|
| Еженедельная сводка | ближайшее **воскресенье, 20:00** | `weekly-summary` |
| Лимит 80% / 100% | сразу после операции | `limit-<categoryID>-<yyyy-MM>-<80\|100>` |
| Долг | **в день возврата, 10:00** | `debt-<debtID>` |

- **Еженедельная сводка пересчитывается при каждом изменении данных и при открытии приложения**: удалить и заново запланировать `weekly-summary` с актуальным текстом за текущую неделю (пн–вс). Так в воскресенье текст всегда верный без фоновых задач. Текст: «Неделя: 186,40 BYN. Больше всего — Кафе (54,00 BYN). На 12% меньше, чем на прошлой неделе». Если трат не было — «На этой неделе трат не было».
- Уведомления о долгах перепланируются при изменении долга; у вернувшихся — снимаются.

## 8. Автоматическая резервная копия

- Владелец **один раз выбирает папку** в «Файлах» (обычно iCloud Drive → Spent) через `UIDocumentPickerViewController(forOpeningContentTypes: [.folder])`.
- Сохраняем **security-scoped bookmark** (`SharedSettings.Key.backupFolderBookmark`). При записи: resolve → `startAccessingSecurityScopedResource()` → запись через `NSFileCoordinator` → `stopAccessing…`. Если bookmark устарел (`isStale`) — пересоздать; если папка недоступна — показать в Настройках «Выберите папку заново».
- Копия пишется **при каждом открытии приложения и после изменений данных**, не чаще раза в 60 секунд.
- Имя: `Spent-yyyy-MM-dd_HH-mm.json`. Хранить **последние 10**, остальные `Spent-*.json` в папке удалять.
- **Про iCloud у бесплатного Apple ID**: собственного iCloud (CloudKit, ubiquity container) у приложения нет и не будет. Это не мешает: пишем в папку, выбранную пользователем в «Файлах», а iCloud Drive работает под основным Apple ID телефона. **Не добавлять iCloud-entitlements** — SideStore с бесплатным аккаунтом их не подпишет.
- Восстановление: Настройки → «Восстановить из копии» → `fileImporter` (JSON) → подтверждение «Текущие данные будут заменены» → `DataFile.save`.

## 12. Архитектура и договорённости по коду

### Структура
```
project.yml                 XcodeGen
App/                        приложение (SwiftUI)
  SpentApp.swift            @main
  Views/                    экраны и компоненты
  Intents/                  App Intents
  Assets.xcassets           иконка, AccentColor
  Spent.entitlements
Shared/                     код, общий для приложения и виджета
  Models.swift              модель + операции над AppData
  SMSParser.swift           разбор SMS
  DataFile.swift            App Group, JSON-файл, SharedSettings
Widget/                     WidgetKit-расширение
Tools/parser_check.py       проверка регулярок парсера без Mac
.github/workflows/build.yml сборка .ipa
```

### Правила
- **Swift 5 language mode**, iOS 17+, только SwiftUI + системные фреймворки (Charts, WidgetKit, AppIntents, UserNotifications, CryptoKit). **Без сторонних зависимостей.**
- **Деньги — `Decimal`.** `Double` — только на входе в Swift Charts.
- **Все изменения данных — через `DataFile.update { … }`** (прочитать с диска → изменить → записать). Не держать `AppData` в памяти как источник истины для записи: App Intent может изменить файл, пока приложение открыто. В приложении — `@MainActor final class SpentStore: ObservableObject` с `@Published data`, методом `mutate(_:)` поверх `DataFile.update` и `reload()` при `scenePhase == .active`. После `mutate`: лимиты → `weekly-summary` → резервная копия → `WidgetCenter.reloadAllTimelines()`.
- Бизнес-логику (операции над данными, статистику, лимиты, прогноз, текст отчёта) класть в `Shared/` как чистые функции/методы над `AppData` — их вызывают и приложение, и App Intent, и виджет. Вью только показывают и вызывают методы.
- В `Shared/` **нельзя** использовать API, недоступные в расширениях (`UIApplication.shared` и т. п.).
- Новые поля модели — опциональные или с дефолтом и через `decodeIfPresent` в `AppData.init(from:)`. Старый файл данных должен открываться всегда.
- Календарь: `Calendar(identifier: .gregorian)`, `locale = ru_RU`, `firstWeekday = 2` (понедельник). Даты — `DateFormatter` с `ru_RU`: «8 ноября», «2–8 ноября», «Ноябрь 2026».
- Суммы: `ru_RU`, 2 знака, пробел-разделитель тысяч, запятая: **«1 234,56 BYN»**.
- Идентификаторы: приложение `com.saevich.spent`, виджет `com.saevich.spent.widget`, группа `group.com.saevich.spent` (через `AppGroup.resolvedID`, не напрямую).
- Маленькие файлы: одна вью — один файл в `App/Views/`.
- В SwiftUI есть свой тип `Transaction` (анимации). Наш `Transaction` из модуля его затеняет — это нормально; анимационную транзакцию SwiftUI в коде не используем.

## 13. Сборка и установка

### CI (`.github/workflows/build.yml`)
`push` в `main` / `claude/**` или ручной запуск → `python3 Tools/parser_check.py` → `brew install xcodegen` → `xcodegen generate` → `xcodebuild … CODE_SIGNING_ALLOWED=NO` → **ad-hoc `codesign` с entitlements** (сначала `.appex`, потом `.app`; без этого App Group потеряется и виджет не увидит данные) → `Payload/Spent.app` → `Spent.ipa` → артефакт `Spent-ipa` + релиз `latest` (релиз — только из `main`; с рабочих веток — только артефакт). При ошибке компиляции лог — в артефакте `build-log`.

### Установка на телефон
1. Скачать `Spent.ipa` из Releases репозитория (на iPhone через Safari).
2. «Поделиться» → SideStore (или в SideStore: My Apps → «+» → выбрать файл). LocalDevVPN должен быть подключён.
3. В SideStore включена настройка **Auto-Fix AppGroup IDs**.
4. Запустить Spent → настроить автоматизацию по инструкции в приложении.

Обновление — так же; данные сохраняются (переустановка поверх).
